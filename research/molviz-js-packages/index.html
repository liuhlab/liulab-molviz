Which JavaScript packages liulab-molviz can build on¶

Research note written for liulab-mbio#575 on 2026-10-17, a sub-issue of map liulab-mbio#572. liulab-molviz will draw in the browser from data mbio writes: a circular and a linear plasmid map, a sequence view with both strands and translations, Sanger trace tracks, a simulated gel, a plate grid, and later 3D protein structures. A command line must also write SVG, PNG and PDF with no browser. The reader promises it inherits: no label overlaps another and a hidden label is counted; bases are real text that find reaches and copy takes; one file opens offline. The map also decided that the viewer draws only what it is given: mbio finds cut sites, translates and places features.

Every claim below was read (from a package's source, docs, LICENSE or npm metadata) or measured (installed, run, downloaded and sized, or counted through the GitHub API) on 2026-10-17, unless its line gives another date. Sizes are the package's own browser build, minified as shipped, then gzip -9. Commit counts are commits on the default branch since 2025-10-17, from gh api .../commits?since=2025-10-17T00:00:00Z --paginate. Claims from memory are marked unverified.

1. The verdict, first¶

SeqViz is a look to copy, not a package to build on (measured and read, 2026-10-17). It does render to an SVG string under Node, but only through a test hook, and four of its traits break a need:

  • The sequence view is virtualised. It mounts five rows at a time. On the server the linear view returned the first 450 of 3,347 bases and nothing else; in a browser, rows off screen are not in the page, so find cannot reach them (read: InfiniteScroll, visibleBlocks starts at Math.min(5, …)).
  • Bases are text but not selectable. Each base is a <tspan> inside one <text>, styled user-select: none; copy goes through SeqViz's own Ctrl+C handler (measured in the server output; read: copyEvent).
  • It computes what mbio computes. It takes enzyme names or {rseq, fcut, rcut} and digests the sequence itself, and takes translation ranges and translates them itself. There is no prop for a cut site at a given position (read: SeqVizProps).
  • Its element kinds are fixed: annotations, primers (linear viewer only), translations, enzymes, highlights, search. children and refs rearrange its two viewers; they add no track kind (read: SeqVizProps).

It also needs React (bundled in its 188 KB build) and fetches Roboto Mono from Google Fonts unless disableExternalFonts is set (read).

The strongest alternative for the prototype is no viewer package: a framework-free SVG core of molviz's own on d3-path, d3-shape and d3-scale, with rbush for collisions and opentype.js for text width (measured: all five run under Node with no DOM, section 5). It is the only route that meets every need at once, about 84 KB gzipped together (sum of the dist files measured, d3-scale's own dependencies excluded). It can draw SeqViz's look, which is flat SVG. Among packaged viewers CGView.js is the runner-up for maps: Apache-2.0, SVG export, a plugin system, and the nearest label rule to ours: priority labels pushed outward until free, then every other label drawn only where it overlaps nothing. It drops the rest without counting them, though the count is one subtraction away. It draws to a canvas: its labels and bases are pixels on screen, its SVG export needs a DOM (d3.select('body')) and svgcanvas, and it has no sequence view. Its label code is worth reading, and Apache-2.0 lets molviz port it with the notice kept.

2. The decisive check: SeqViz under Node¶

2.1 What was run¶

In a fresh empty directory outside the repo (measured, 2026-10-17; Node 26.10.0, pnpm 12.4.1):

echo '{"name":"seqviz-env","private":true}' > package.json
pixi exec -s nodejs -s pnpm -- pnpm add seqviz react react-dom
# → seqviz 3.10.25, react 19.3.1, react-dom 19.3.1

The record was docs/examples/pUC19-GFP/product.dna read with Biopython's SnapGene reader: 3,347 bp, 21 features, 11 of them primer_bind, passed as SeqViz annotations and primers, with twelve enzymes (EcoRI, SacI, KpnI, SmaI, BamHI, XbaI, SalI, PstI, SphI, HindIII, NcoI, BsaI) and the GFP span as a translation. The script lived in a separate directory and loaded the packages by path:

// node seqviz-ssr.cjs ENV_DIR RECORD_JSON OUT_DIR
const req = createRequire(path.join(envDir, "package.json"));
const React = req("react");
const { renderToStaticMarkup } = req("react-dom/server");
const seqviz = req("seqviz");
const base = {
  name: rec.name, seq: rec.seq, annotations, primers, enzymes,
  translations: [{ start: gfp.start, end: gfp.end, direction: gfp.direction }],
  disableExternalFonts: true,
  style: { width: "1000px", height: "800px" },
};
if (process.env.TEST_SIZE) base.testSize = { width: 1000, height: Number(process.env.TEST_SIZE) };
for (const viewer of ["circular", "linear", "both"]) {
  renderToStaticMarkup(React.createElement(seqviz.SeqViz, { ...base, viewer }));  // route 1
  seqviz.Viewer(undefined, { ...base, viewer }).renderToString();                 // route 2
}

Each output's <svg> was pulled out and rasterised with vl_convert.svg_to_png to look at it.

2.2 What came out¶

Route Size given Result
Viewer(…).renderToString(), the README's "server-side rendering" call any Throws ReferenceError: document is not defined, for all three viewers
renderToStaticMarkup(<SeqViz>) style only Empty containers, no <svg>: width and height come from a resize detector, which reports 0 on the server
renderToStaticMarkup(<SeqViz>) with testSize 1000 × 800 test hook Circular: one complete <svg>, 24,774 bytes, 24 <text>, 51 <path>: ring, ticks, feature arrows, labels on the arc through <textPath> (lacZα, ori, AmpR, GFP), outside labels with leader lines (AmpR promoter, ATGA junction, NcoI, BsaI ×2, lac promoter, lac operator) and one group MCS,+1. No primers: the circular viewer does not draw them
same test hook Linear: five <svg> rows, both strands, primers above and below, the GFP translation as boxed residues, annotations, index — bases 1 to 450 only
same, testSize height 60,000 test hook Still five rows: the window is fixed at five blocks, not sized to the height

testSize is documented only in SeqViewerContainer.d.ts: "a forced height/width that overwrites anything from sizeMe. For testing" (read). SeqViz passes every prop through to the container, so it reaches it (read). The layout itself needs no DOM: label widths are estimated at a fixed 7.2 px per character (CHAR_WIDTH), and nothing is measured (read).

So: a SeqViz circular map can become SVG text on a command line through an undocumented hook; a whole sequence view cannot.

rbush collides: true false
opentype.js advance 'BsaI' @12px: 24.012
fontkit advance 'BsaI' @12px: 24.012

@d3fc/d3fc-label-layout failed with ERR_MODULE_NOT_FOUND from its own index.js, and the d3fc umbrella threw "d3fc-element depends on Custom Elements (v1)" at load.

A text width from opentype.js matches the browser only if the page draws with the same font, so the font file is inlined in the page and read by the command line. SeqViz avoids the question by estimating 7.2 px per character; CGView.js asks a canvas.

The pure-function route has one working example. @carabennemsi/plasmid renders the pUC19-GFP record to a standalone SVG string under Node (measured: 12,328 bytes, 13 <text>). Its labels show why that is not enough alone: lacZα, GFP, AmpR and ori sit on their arcs, three narrow features and the NcoI site get outside labels, and the other 14 features, 10 primers among them, get none, with no count.

Open gaps¶

  • SeqViz in a real browser, offline. Whether Ctrl+F finds bases is inferred from the source (user-select: none, five mounted rows), not tried. The SeqViz prototype should open its page with the network off and search for a base run outside the first rows.
  • SeqViz on a crowded map. The 30-label variant of plasmid-map-packages.md was not drawn, so how often name,+N groups or overlaps there is unmeasured.
  • Whether SeqViz would take a documented size prop in place of testSize, and an option to mount every row. Not asked upstream.
  • CGView.js under jsdom with svgcanvas was not tried, so its command-line cost is read, not measured.
  • @molbiohive/hatchlings was not compiled and rendered with svelte/server; it is the one package covering trace, gel and plate, but is seven months old with two stars and no commit since March.
  • @nitro-bio/sequence-viewers was not installed: only its README was read.
  • Mol* headless was not run; whether the native gl module builds under the pinned Node on osx-arm64 and linux-64 is unknown, and the v6 reorganisation on master may move the API.
  • sage's trace code was not read, nor whether sanger-viewer's exportSvg draws a reference row.
  • Bundlephobia was not used; sizes are the packages' own builds. The own-core total is a sum of dist files, not a bundled build.
  • OVE's headless behaviour and label rule at 0.8.42 were not re-read.
  • JSmol, vega-label, tagmap.js were not checked.
  • This note is not in docs/research/index.md: the branch carries only this file.
